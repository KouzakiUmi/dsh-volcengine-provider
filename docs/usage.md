# 账号与使用说明

[返回主页](../README.md) · [接口依据](arkcli-contract.md) · [验证范围](validation.md)

## 两种接入方式

| 方式 | 适用场景 | 推理鉴权 | 额度鉴权 |
|---|---|---|---|
| 网页登录 | 希望通过官方账号接入 | 隔离 ArkCli profile 的默认 Key | 同一隔离 CLI 身份 |
| 凭据引用 | 宿主已有对应 Key / IAM 凭据 | 两套套餐各自的 API Key 引用 | IAM AK/SK 引用 |

两套套餐独立选择账号。OAuth 绑定后，不会因为某套套餐缺失就悄悄退回另一个身份或凭据池。

## 网页登录

1. 预先安装官方 [ArkCli](https://github.com/volcengine/ark-cli)，确认 CLI 版本；当前实现对照 `1.0.37` 契约。
2. 打开 **设置 → dsh-volcengine-provider → 新增账号**。填写小写账号 ID 和展示名；OAuth 账号的 Key / AK / SK 引用均可留空。
3. 点击 **网页登录**。阅读页内确认提示，再点击 **确认并打开官方登录页**。
4. CLI 在系统默认浏览器启动官方 OAuth。确认网页实际授权账号，在官方流程中完成验证。
5. 插件核验登录状态，并按 profile 类型分别绑定个人 Agent Plan / Coding Plan。不存在的套餐不绑定；同类有多个 profile 时不猜选。
6. 分别选择订阅卡片上的账号，再拉取模型、刷新额度。

插件调用 `arkcli auth login volc-sso`。浏览器启动、OAuth 请求、回调及凭据保存均由官方 CLI 管理。

### 登录状态

- **启动中 / 等待授权**：在官方网页继续操作，不要重复启动登录。
- **核验中**：OAuth 进程已结束，正在确认身份和套餐 profile。
- **成功**：身份与个人套餐 profile 已确认；不代表额度接口或推理已验收。
- **取消 / 失败 / 超时**：可以刷新状态后重试；CLI 可能已经写入部分隔离凭据，取消不是凭据删除操作。

初次登录若要求选择消费场景、签署协议或创建/轮换 Key，插件不会代为完成；这仍是需要在官方流程中处理的前置条件。非 TTY 首登尚待真实账号验收。

### 找不到 CLI

可自动发现 PATH 相邻的官方原生二进制。若自动发现失败，在插件配置中填写：

```yaml
arkCliPath: '<官方 ArkCli 原生可执行文件的绝对路径>'
```

Windows 指向官方 `.exe`，不是 `.cmd` / `.bat` 包装器。插件不会安装、下载或升级 CLI。

## 凭据引用模式

默认账号沿用：

```text
Agent Plan:  ARKCLI_AGENT_PLAN_API_KEY
Coding Plan: ARKCLI_CODING_PLAN_API_KEY
IAM AK:      VOLC_ACCESSKEY
IAM SK:      VOLC_SECRETKEY
```

这些是**变量名 / 宿主凭据引用名**，不是密钥值。每个账号可以填写不同的引用。

- 推理 API Key 不用于管控面签名。
- 没有 AK/SK 时，模型推理仍可能正常，只是此模式下无法查额度。
- 凭据服务可用时按宿主解析链读取；没有该服务时使用启动环境。
- 修改启动环境通常需要让目标 Host 进程重新继承；不要仅根据另一个终端中的值判断宿主已配置。

## 模型目录

分别点击两个订阅卡片上的 **拉取模型**。该操作不购买套餐、不改官方默认模型，也不切换原 CLI 的默认 profile。

- 拉取前需要已登录的隔离账号，或已知的隔离 CLI profile。
- API Key 引用本身不等于控制面身份，不能凭推理 Key 推断模型目录查询可用。
- `output_name` 优先作为调用 ID，`model_name` 只作展示。
- 空目录保留为空；损坏缓存显示错误，不伪装成有效目录。
- 本地兼容快照只作为起点；新模型使用保守文本能力，不代表官方完整能力。

路由更新先校验，再原子替换。失败时会保留此前可用路由并显示错误；修正账号或重新拉取目录后重试，不把失败变更当作已生效。

## 额度语义

| 套餐 | 窗口 | 展示规则 |
|---|---|---|
| Coding | 5 小时 / 周 / 月 | 上游已用百分比；不编造请求次数或绝对量 |
| Agent | 文本/向量 5 小时与周、全能力月、日能力限额 | AFP 绝对 used / limit 与剩余百分比；各能力范围分组 |

重置时间不是套餐到期时间。接口成功也不保证当前请求一定可续用；数字不作为计费依据。

额度按账号和订阅隔离缓存，默认 60 秒；界面的 **刷新额度** 发起强制刷新。推理 Key 使用 30 秒 Host 内存缓存，并共享同账号、同 profile 的并发读取；引用或账号变更、卸载时失效。

## 数据保存位置

默认数据根位于用户 home 下 `.dsh/dsh-volcengine-provider`：

```text
state.json                         账号标签、引用、选择、profile 名、模型缓存
accounts/<account-id>/.arkcli/      官方 CLI 管理的隔离身份与凭据
```

可通过插件的 `statePath` 指定元数据文件位置；账号目录随其父目录定位。

- 插件元数据不保存明文 API Key / AK / SK / token / Cookie。
- 官方 CLI 仍需保存自身认证信息；插件不是一个替代 CLI 的加密凭据库。
- 删除账号只移除元数据，不自动删除隔离身份目录。
- 不覆盖或迁移原有用户 home 下的 CLI 身份。
- 同一账号重登请确认授权身份；系统浏览器 Cookie 不由插件清理。

## 常见问题

### 旧路由还在，是重复安装了吗？

不一定。插件新路由为 `volcengine-agent-plan` / `volcengine-coding-plan`；原有 `arkcli-agent-plan` / `arkcli-coding-plan` 保持不变。先并存验收，再自行切换会话模型；插件不删除旧配置。

### 登录成功，为什么额度仍失败？

OAuth 身份、套餐 profile、额度接口和推理是不同验证层。检查所选订阅、账号、权限、网络与 CLI 版本；raw 额度请求和响应形态仍有待真实验收的部分，见[接口说明](arkcli-contract.md)。

### 如何反馈？

提供 DSH **Core** 版本、ArkCli 版本、订阅类型、脱敏后的错误文案即可。不要提交密钥、授权链接、完整 debug 输出或隔离凭据目录。[创建 Issue](https://github.com/KouzakiUmi/dsh-volcengine-provider/issues)。
