# 账号与使用说明

[返回主页](../README.md) · [接口依据](arkcli-contract.md) · [验证范围](validation.md)

## 两种接入方式

| 方式 | 适用场景 | 推理鉴权 | 额度鉴权 |
|---|---|---|---|
| 网页登录 | 希望通过官方账号接入 | 隔离 ArkCli profile 的默认 Key | 同一隔离 CLI 身份 |
| 凭据引用 | 宿主已有对应 Key / IAM 凭据 | 两套套餐各自的 API Key 引用 | IAM AK/SK 引用 |

两套套餐独立选择账号。OAuth 绑定后，不会因为某套套餐缺失就悄悄退回另一个身份或凭据池。

## 网页登录

1. 预先安装官方 [ArkCli](https://github.com/volcengine/ark-cli)，确认 CLI 版本；当前实现对照 `1.0.37` 契约。
2. 打开 **设置 → 火山方舟 Provider**。没有账号时直接点击 **网页登录**；已有账号需要添加另一个身份时点击 **登录其他账号**。已有账号重登则点击该账号卡片里的 **网页登录**。
3. 阅读页内确认提示，再点击 **确认并打开官方登录页**。新增登录身份会自动创建本地账号，无需填写账号 ID 或密钥引用；**新增账号**保留给手动配置凭据引用的场景。
4. CLI 在系统默认浏览器启动官方 OAuth。确认网页实际授权账号，在官方流程中完成验证。
5. 插件核验登录状态，并按 profile 类型分别绑定个人 Agent Plan / Coding Plan。不存在的套餐不绑定；同类有多个 profile 时不猜选。
6. 登录后页面自动显示官方用户名，本地备注单独保留；账号区标明每套套餐的绑定和使用关系。在账号卡片点击 **用于 Agent套餐 / 用于 编程套餐** 可选择该账号并启用对应套餐；也可在套餐卡片分别选择账号和启停。之后查看模型与刷新额度。

已登录的旧账号会尝试只读补齐官方身份摘要。官方未返回用户名时显示账号 ID 或本地备注，不把本地备注冒充官方用户名。高级凭据引用、Profile 和路由标识按需展开。

插件调用 `arkcli auth login volc-sso`，使用官方 same-device OAuth 与本地回调。授权页在用户普通系统默认浏览器打开，可正常使用该浏览器的密码管理器、扩展、自动填充与通行密钥；浏览器启动、OAuth 请求、回调及凭据保存均由官方 CLI 管理。插件不操作登录网页，也不读取密码或浏览器 Cookie。隔离的是 CLI 凭据目录，不要求用户换一个专用浏览器登录。

### 登录状态

- **启动中 / 等待授权**：在官方网页继续操作，不要重复启动登录。
- **核验中**：OAuth 进程已结束，正在确认身份和套餐 profile。
- **暂时无法查询进度**：只是进度通信异常，不代表 OAuth 已停止；页面会退避重试，取消入口仍保留。启动响应丢失时会先读回已有任务，避免重复登录。
- 页面顶部 **刷新状态** 可同步其他窗口修改的账号与鉴权状态。
- **成功**：身份与个人套餐 profile 已确认；不代表额度接口或推理已验收。
- **取消 / 失败 / 超时**：可以刷新状态后重试；CLI 可能已经写入部分隔离凭据，取消不是凭据删除操作。

初次登录若要求选择消费场景、签署协议或创建/轮换 Key，插件不会代为完成；这仍是需要在官方流程中处理的前置条件。非 TTY 首登尚待真实账号验收。

### 找不到 CLI

可自动发现 PATH 相邻的官方原生二进制。若自动发现失败，在插件配置中填写：

```yaml
arkCliPath: '<官方 ArkCli 原生可执行文件的绝对路径>'
```

Windows 指向官方 `.exe`，不是 `.cmd` / `.bat` 包装器。插件不会安装、下载或升级 CLI。

## 凭据引用模式

默认账号沿用：

```text
Agent Plan:  ARKCLI_AGENT_PLAN_API_KEY
Coding Plan: ARKCLI_CODING_PLAN_API_KEY
IAM AK:      VOLC_ACCESSKEY
IAM SK:      VOLC_SECRETKEY
```

这些是**变量名 / 宿主凭据引用名**，不是密钥值。每个账号可以填写不同的引用。OAuth 绑定存在时，编辑这些引用不会切换鉴权方式；需要凭据引用接入时，使用独立的未绑定 OAuth 账号。

- 推理 API Key 不用于管控面签名。
- 没有 AK/SK 时，模型推理仍可能正常，只是此模式下无法查额度。
- 凭据服务可用时按宿主解析链读取；没有该服务时使用启动环境。
- 修改启动环境通常需要让目标 Host 进程重新继承；不要仅根据另一个终端中的值判断宿主已配置。

## 模型目录

分别点击两个订阅卡片上的 **拉取模型**。该操作不购买套餐、不改官方默认模型，也不切换原 CLI 的默认 profile。

- 拉取前需要已绑定该套餐的 OAuth 账号，或该账号隔离目录内的 CLI profile。条件未满足时按钮禁用并说明原因；凭据引用账号仍可使用本地模型快照，不必为使用快照先登录 CLI。
- API Key 引用本身不等于控制面身份，不能凭推理 Key 推断模型目录查询可用。
- `output_name` 优先作为调用 ID，`model_name` 只作展示。
- 空目录保留为空；损坏缓存显示错误，不伪装成有效目录。
- 本地兼容快照只作为起点；新模型使用保守文本能力，不代表官方完整能力。

路由更新先校验，再原子替换。失败时会保留此前可用路由并显示错误，同时分别标明**所选账号**和**实际生效账号**。设置可能已保存，但实际调用仍使用旧路由；修正账号或重新拉取目录后重试。

## 套餐与模型开关

套餐卡片的启用状态和账号选择分别保存。关闭 Agent Plan 不影响 Coding Plan；重新启用时保留之前所选账号。未选择账号时，套餐没有可注册的模型路由。

模型列表中的开关只影响该账号、该套餐里的这个模型。停用后从模型选择器中移除，但仍保留参数，便于稍后重新启用。拉取目录不会清空这些设置。

## 模型参数

展开模型参数，可以覆盖上下文长度、默认输出 token、温度、思考档位映射、默认档位和思考模式。数值留空表示继承；继承思考档位读取目录默认映射，而不是此前保存的自定义映射。恢复默认会清除该模型全部覆盖值并恢复启用，停用模型的按钮会明确显示 **恢复默认并启用**。设置按账号、套餐、模型保存，切换账号不会套用另一账号的参数。

- 上下文和输出 token 为正整数，输出值不能大于上下文；温度范围为 0 到 1。
- 默认思考可跟随兼容默认、明确不强制，或选择已声明的档位。非思考模型不会被强制设为 low。
- 原生 effort 模式发送映射值；预算模式把档位转换为思考 token 预算，两者含义不同。
- 单次请求显式提供的参数优先；思考开启时温度可能被传输层忽略，最终 token 数还受思考预算和上下文限制。
- 仅声明服务端确实支持的档位；新模型的保守默认不等于官方完整能力。详细字段见[模型管理设计](model-management.md)。

## 额度语义

| 套餐 | 窗口 | 展示规则 |
|---|---|---|
| Coding | 5 小时 / 周 / 月 | 上游已用百分比；不编造请求次数或绝对量 |
| Agent | 文本/向量 5 小时与周、全能力月、日能力限额 | AFP 绝对 used / limit 与剩余百分比；各能力范围分组 |

重置时间不是套餐到期时间。接口成功也不保证当前请求一定可续用；数字不作为计费依据。

额度按账号和订阅隔离缓存，默认 60 秒；界面的 **刷新额度** 发起强制刷新。额度查询仅占用对应套餐的查询按钮，不锁住账号编辑或切换；切换后可立即查询新账号，迟到的旧结果会被丢弃。推理 Key 使用 30 秒 Host 内存缓存，并共享同账号、同 profile 的并发读取；引用或账号变更、卸载时失效。

## 数据保存位置

默认数据根位于用户 home 下 `.dsh/dsh-volcengine-provider`：

```text
state.json                                      账号、公开身份摘要、引用、套餐、模型及登录绑定
accounts/<account-id>/.arkcli/                   旧版登录的兼容目录
accounts/<account-id>/sessions/<home-id>/.arkcli/ 每次新登录独立的官方 CLI 身份目录
```

可通过插件的 `statePath` 指定元数据文件位置；账号目录随其父目录定位。

模型管理使用版本 2 元数据。读取旧版本 1 文件只在内存中迁移，首次保存修改时才写回版本 2。新版 OAuth 绑定增加了独立登录目录标识；旧插件不识别该标识，回退时须同时恢复对应旧版元数据备份，不能直接把新版登录绑定交给旧插件。

- 插件元数据不保存明文 API Key / AK / SK / token / Cookie。
- 官方 CLI 仍需保存自身认证信息；插件不是一个替代 CLI 的加密凭据库。
- 删除账号只移除元数据，不自动删除隔离身份目录。
- 不覆盖或迁移原有用户 home 下的 CLI 身份。
- 同一账号重登请确认授权身份；系统浏览器 Cookie 不由插件清理。每次登录使用新目录，核验成功后才切换绑定，失败或取消保留上次可用身份；旧目录保留，不自动删除凭据。
- 多实例写入通过独占锁与磁盘版本检查防止覆盖。冲突后刷新页面同步最新状态；异常退出若残留 `state.json.lock`，须确认没有实例正在写入后再清理该锁文件。

## 常见问题

### 旧路由还在，是重复安装了吗？

不一定。插件新路由为 `volcengine-agent-plan` / `volcengine-coding-plan`；原有 `arkcli-agent-plan` / `arkcli-coding-plan` 保持不变。先并存验收，再自行切换会话模型；插件不删除旧配置。

### 登录成功，为什么额度仍失败？

OAuth 身份、套餐 profile、额度接口和推理是不同验证层。检查所选订阅、账号、权限、网络与 CLI 版本；raw 额度请求和响应形态仍有待真实验收的部分，见[接口说明](arkcli-contract.md)。

### 如何反馈？

提供 DSH **Core** 版本、ArkCli 版本、订阅类型、脱敏后的错误文案即可。不要提交密钥、授权链接、完整 debug 输出或隔离凭据目录。[创建 Issue](https://github.com/KouzakiUmi/dsh-volcengine-provider/issues)。
